# Architecture

> Post-2.0 refactor. For the findings that drove this shape, see
> [`AUDIT.md`](AUDIT.md); for the execution record, see [`../PLAN.md`](../PLAN.md).

## The two-layer model

```
┌─────────────────────────────────────────────────────┐
│  winky-wonky-react     thin wrappers, controlled     │
│  (packages/…-react)    `value` prop → setValue()     │
├─────────────────────────────────────────────────────┤
│  winky-wonky           24 components: DOM + ARIA +   │
│  (src/)                CSS + core primitives         │
├─────────────────────────────────────────────────────┤
│  @winky/core           springs · gestures · audio ·  │
│  (packages/winky-core) media helpers (headless)      │
└─────────────────────────────────────────────────────┘
```

npm workspaces monorepo; single root lockfile; `npm run test:all` runs every
package's vitest suite. CI (`.github/workflows/ci.yml`) runs install, tests,
both builds, and type generation on push/PR.

## `@winky/core` — the engine

- **`spring.js`** — one damped-harmonic-oscillator implementation
  (`createSpring`), advanced via the closed-form solution (unconditionally
  stable, no Euler blow-ups). Framer-Motion-scale `stiffness`/`damping`/`mass`.
  The internal rAF loop runs only while moving; `onRest` fires and the loop
  stops — the "idle when settled" contract every consumer follows.
- **`gesture.js`** — `addPointerDrag`: unified pointer-events drag with
  down/move/up/cancel lifecycle and full teardown.
- **`audio.js` / `soundRecipes.js`** — `AudioSynth`: lazy AudioContext,
  gesture-gated (autoplay policy), master gain, mute/volume; `soundRecipes`
  are the composable oscillator presets (tick/clack/slide/hum).
- **`media.js`** — lazily-initialized `matchMedia` helpers for
  `prefers-reduced-motion`, `prefers-reduced-sound`, `pointer: coarse`, with
  change subscriptions.

Everything is SSR-safe: no `window`/`document` access at module scope,
guarded lazy init everywhere. `sideEffects: false`, tree-shakeable.

## `winky-wonky` — the component library

- **Factory pattern:** every component is `createX(options)` returning an
  instance object `{ el, destroy, getValue?, setValue?, setOptions? }` — not a
  bare DOM node. `setValue` updates DOM + ARIA and never fires `onChange`
  (controlled-component contract). `onChange` fires exactly once per actual
  value change.
- **Core adoption:** `TiltSlider` is fully rebuilt on `createSpring` +
  core gestures/audio (the flagship proof). The remaining components consume
  the core through compatibility shims — `src/components/utils.js` and
  `src/components/audioSynth.js` re-export from `@winky/core` — pending the
  owner's keep-vs-recipes decision (PLAN.md Phase 5 annotation).
- **Shared component utils** (`src/components/utils.js`): `setAria` batch
  attribute setter, `makeFocusable`, `onKeyActivation` (Enter/Space),
  `trapFocus` for modals — plus the `@winky/core` re-exports.
- **CSS:** split per component under `src/styles/`, aggregated by
  `src/winky-wonky.css` (the published `winky-wonky/style.css` export). All
  shipped class names are `winky-`-prefixed; all theme tokens are `--winky-*`
  variables. Known cross-file deps: `slinkyAccordion` uses
  `winky-squash-press` (mischievousButton.css); `suspiciousEyes` uses
  `winky-quill-input` (typewriterInput.css).
- **Accessibility:** ARIA roles/states on every interactive component, full
  keyboard support (arrows, Home/End, Enter/Space, Escape), focus traps in
  modals, `prefers-reduced-motion` and `prefers-reduced-sound` respected live
  (media-query change listeners), unified pointer events for touch.
- **Types:** JSDoc-typed source; `.d.ts` generated by
  `tsc --allowJs --declaration` (`npm run types`), shipped via the `types`
  fields in `exports`.

## Theme system

- `:root` = Dark Premium (default, no `data-theme` attribute)
- `[data-theme="anderson"]` = Wes Anderson preset
- `[data-theme="burton"]` = Tim Burton preset
- All tokens use the `--winky-*` prefix.

## Storybook (never published)

`.storybook/` + `stories/` — the component gallery/docs (`npm run
storybook`). One `*.stories.js` file per component, with `argTypes` driving
live Controls; none of this ships in the library. The pre-2.0 custom
playground (`src/playground/`, `index.html`) served the same purpose and was
removed in favor of Storybook.

## Builds

- `npm run build-storybook` — static Storybook site.
- `npm run build:lib` — library IIFE bundle (`dist/winky-wonky.min.js`, for
  CDN `<script>` use) + ES module + CSS. The copy-css step ships both
  `winky-wonky.css` and `src/styles/` together (the aggregate uses relative
  `@import`s — they must travel as a pair).
- `packages/winky-wonky-react`: Vite lib mode → compiled ESM `dist/index.js`
  (no raw JSX is ever published); react/react-dom/winky-wonky stay external
  as peers.
